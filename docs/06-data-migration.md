# 数据迁移与备份

## 数据在哪里

```text
<解压目录>\data\store.json       结构化课程数据
<解压目录>\data\bootstrap.json   前端启动快照
<解压目录>\data\media\           录音、TTS、截图、MP4、交付包、HTML 介质
<解压目录>\data\secrets.json     可选的模型 Key
```

少量数据不一致通常来自只复制了 `store.json`，没有复制 `media`。课程和媒体必须一起迁移。

## 方式一：带数据整体迁移

1. 关闭系统。
2. 备份 `data`。
3. 将整个 `kexu-portable-win-x64` 目录复制到新电脑。
4. 在新电脑启动 `start-kexu.cmd`。
5. 在运行设置中重新填写模型 Key。
6. 打开课程，抽查讲稿、课件、录音和成片。

这种方式包含程序版本，迁移后不会出现新旧代码混用。

## 方式二：只迁移课程数据

1. 在旧电脑执行 `backup-data.cmd`。
2. 在新电脑安装同版本或更新版本的课序系统。
3. 关闭新电脑上的系统。
4. 备份新系统的 `data` 目录。
5. 解压旧电脑的课程数据备份。
6. 将备份中的 `data` 内容复制到新系统 `data`。
7. 启动并运行 `check-env.cmd`。

不要只覆盖 `store.json`。媒体目录也要一起复制。

## 使用备份脚本

```bat
backup-data.cmd
```

默认输出：

```text
backups\kexu-data-YYYYMMDD-HHmmss.zip
```

ZIP 根目录是 `data`，不包含：

- `secrets.json`
- `ui-check`
- `shot-test`
- `tts-test`
- `backups`

这样备份可以安全交给课程团队，不会携带模型 Key。

## 手动备份

停止系统后复制整个 `data` 目录。若有大量视频，建议使用文件复制而不是压缩，节省时间。

恢复时先保留一份现有 `data` 的副本，再替换，避免误覆盖。

## 模型 Key 迁移

不要把 `data\secrets.json` 放进通用备份包。新电脑上通过界面重新填写，或者在新电脑的 `config\kexu.env.cmd` 中配置环境变量。

如果确需迁移 Key：

- 只在自己的受控设备之间传输。
- 使用密码管理器或加密容器。
- 迁移后删除中间文件。

## 版本升级

升级程序但保留数据：

1. 备份当前 `data`。
2. 解压新版本到新目录。
3. 将旧 `data` 复制到新版本根目录。
4. 启动新版本。
5. 抽查课程、媒体、工作流与引擎配置。

不要将新版本程序文件覆盖到旧版本目录后再回滚。新旧 `node_modules` 与构建产物可能不兼容。

## 迁移检查清单

- 课程数量一致
- 每个课程有讲稿与课件
- 录音可以播放
- 成片可以下载与播放
- 交付包入口可以打开
- 介质 HTML 可以访问
- 教师记忆存在
- 智能体、Skill、引擎与工作流配置存在
- 模型与 TTS 可以测试
