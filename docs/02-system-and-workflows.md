# 系统与工作流

## 产品边界

这是一个面向教师和课程制作团队的生产系统，不是课程展示网站。左侧是模块目录，主区是当前课程的生产卷宗，右侧运行抽屉承载智能体、运行状态与调度信息。

## 左侧功能模块

- 工作台：查看课程、生产状态和下一步动作。
- 新建课程：选择工作流并录入或口述课程信息。
- 课程项目：课程列表、阶段、项目详情。
- 讲稿工坊：结构化讲稿展示、编辑、保存、确认、选中批注与修改意见。
- 课件工坊：按讲稿生成和编辑课件，可配置不同生产引擎。
- 声音与录制：AI 旁白、教师试讲、录音、翻页事件、语音定位。
- 成片渲染：时间轴、渲染状态、MP4 下载。
- 课程交付：视频、封面、介质包与编排后的 HTML 入口。
- 介质工坊：知识图谱、认知地图、概念卡、一图读懂、时间线、问答题等 HTML 介质。
- 智能体平台：Agent 配置、启停、调试与运行记录。
- Skill 中心：讲稿、分析、课件、质检、介质等能力。
- 教师记忆：年级、学科、学校、备课经验、教学偏好与心得。
- 运行设置：模型、TTS、超时、重试、兜底与能力诊断。

右侧运行抽屉默认折叠。它有三个页签：

- 智能体：当前 Agent、Skill 与运行轨迹。
- 运行：任务队列、进度和错误。
- 调度：工作流与阶段状态。

可用右缘触发条打开，也可用 `Esc` 或遮罩关闭。

## 三种默认课程模式

### 全自动

输入主题、学段、学科、时长、想法与价值引领。系统依次完成讲稿、确认、课件、AI 旁白和渲染。适合快速出草稿，再由教师做一轮人工复核。

### 口语稿驱动

教师先按自己的表达讲一遍。系统保留录音，进行语音转写与时间定位，再按讲述节拍生成对应课件，最后合成视频。重点是“教师原声优先”，页面服从讲述。

### PPT 驱动

教师确认讲稿后生成课件，再对照 PPT 试讲。系统录音并记录翻页时间点，将声音、画面和页面事件对齐后合成。重点是“画面先定，讲述跟随”。

三种模式不是三套割裂页面，而是同一流水线上的不同默认工作流。

## 教师试讲与录制

教师试讲是一块全屏试讲台：上方是课件，下方是字幕式讲稿。讲稿按当前页自动排版，字号随内容自适应，整段完整显示，不需要翻页或上下滑动。课件右侧是翻页键，左右箭头直接切页，同时记录翻页时刻。

试讲台采集两路信息：

- 声音：麦克风录音，并按浏览器能力做实时转写。
- 教师画面：在“运行设置 → 生产环境”打开“试讲时录制教师画面”后，试讲台右下角出现画面预览，可随时关闭。画面与声音同时开始、同时结束。

声音、画面与课件翻页事件一起保存，合成成片时教师画面叠在课件右下角，音画与页面切换保持同步。

## 可配置工作流

系统把工作流与环节分开建模：

- 课程模式决定默认走哪条工作流。
- 工作流由有序环节组成。
- 每个环节可以选择生产引擎与 Agent / Skill。
- 环节可以迭代，工作流也可以新建。

当前发行版预置三种默认工作流。后续可以在配置层新增模式，而无需复制整套页面。

## 生产引擎与 Skill 解耦

课件生成不是一个写死的动作。系统支持配置多个生产引擎，例如：

- 文字课件引擎
- 结构课件引擎
- 文生图课件引擎
- 其他可扩展引擎

每个引擎后面可以挂接一个 Agent / Skill。界面中的析课、讲稿、课件、介质等过程都按这个思路解耦：默认引擎保证开箱可用，新建引擎承接更专门的生成策略。

一个稳定约定是：引擎负责“怎么生产”，Skill 负责“生产规则与输出契约”，Agent 负责编排和上下文。

## 讲稿与课件的对应关系

讲稿段落与课件页面是一一对应的，顺序完全一致。每段讲稿带一个角色：

| 角色 | 作用 | 对应页面 |
| --- | --- | --- |
| intro 主题引入 | 讲清这节课的主题与要解决的问题 | 第 1 页 封面 |
| objectives 学习目标 | 把学习目标说成可检验的收获 | 第 2 页 学习目标 |
| body 正文 | 情境、拆解、机制、证据、迁移 | 中间各页 |
| close 收束 | 回扣开场问题，收拢方法与价值 | 最后一页 总结 |

系统在三个层面保证这层对应关系：

1. 生成讲稿时，模型被要求按 intro / objectives / body / close 的顺序产出段落。
2. 生成课件时，页面按讲稿段落逐一生成，封面绑定 intro、学习目标页绑定 objectives。
3. 读取课程时自动规整：缺主题引入或学习目标就补齐，页面与段落重新对齐。

老师改过手的内容不会被覆盖；自动补写的主题引入、学习目标与收束会随课程标题和目标自动更新。

在讲稿工坊的左侧大纲里，每段都标着角色和对应页码；课件工坊选中任意一页，右下角显示这一页要讲的那段口播原文。

## 讲稿工坊

讲稿使用结构化段落展示，而不是一大段纯文本。教师可以：

- 直接修改标题、段落、旁白、视觉任务与备注。
- 保存修改。
- 确认讲稿并进入下一环节。
- 针对整篇或具体段落提交修改意见。
- 选中文字并附带引用提交意见。
- 查看意见状态并标记已解决。

讲稿一旦修改，已有的下游课件、渲染和交付会失效，避免成片与讲稿不一致。

## 教师记忆

教师记忆用于保存跨课程的个人上下文，例如：

- 任教学段与学科
- 学校与教学环境
- 常用表达风格
- 备课经验与心得
- 对练习、案例、价值引领的偏好

新建课程时可以口述课程想法。系统会分析语音内容，自动填入主题、学段、学科、时长、模式、想法与价值引领，教师确认后再创建课程。

## 介质工坊

介质工坊生成视频之外的教学介质。所有介质最终都是 HTML，HTML 是统一容器：

- 知识图谱
- 认知地图
- 概念卡
- 一图读懂
- 时间线
- 问答题
- 后续新增的介质类型

每种介质有独立的 Skill 与生成契约。生成的 HTML 可独立打开，也可进入课程交付包。

## 交付包

发布课程后，系统生成一个以 `index.html` 为入口的交付包：

- 入口中包含视频微课。
- 课程介质以链接或嵌入方式组织。
- 介质可以按视频时间点配置出现位置。
- 关键概念出现时，可在视频下方展示对应概念卡等介质。

这意味着交付不是“一个 MP4 文件”，而是“视频 + 可视化教学介质 + 访问入口”。

## 数据模型

核心数据保存在 `data\store.json`：

- `projects`：课程、讲稿、课件、录音、渲染、交付
- `agents`：智能体配置
- `skills`：Skill 定义
- `engines`：生产引擎
- `workflows`：模式对应的工作流
- `memory`：教师记忆
- `settings`：运行设置
- `activity`：活动与运行记录

媒体与 HTML 保存在 `data\media\<project-id>`。备份时两者必须一起处理。
