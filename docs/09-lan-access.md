# 局域网访问

系统默认只监听 `127.0.0.1`，适合本机使用。需要让同一局域网里的另一台电脑打开系统时，用局域网启动方式。

## 一键启动

在源码目录双击 `start-lan.cmd`，或执行：

```powershell
npm run start:lan
```

脚本会做三件事：

1. 以 `HOST=0.0.0.0` 启动服务，默认端口 `8787`，HTTPS 录音端口 `8788`。
2. 自动识别当前电脑的局域网 IP，并打印访问地址。
3. 打开本机浏览器。加 `-NoBrowser` 可以不自动打开。

停止服务：

```powershell
npm run stop:lan
```

## 访问地址

假设本机局域网 IP 是 `192.168.1.174`，另一台电脑应访问：

```text
http://192.168.1.174:8787
```

`192.168.1.1` 通常是路由器网关，不是这台电脑，不能用来访问系统。IP 可以在启动脚本输出里看到，也可以在本机执行 `ipconfig` 查看。

## 防火墙

第一次使用前，用管理员权限的 PowerShell 执行一次：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\enable-lan-access.ps1
```

脚本只放行本地子网到 TCP `8787`、`8788`，不会把服务暴露到公网。

## 局域网录音

浏览器只在安全上下文中允许麦克风。`http://192.168.x.x` 属于非安全来源，Edge 可能直接拒绝录音。

两种处理方式：

1. 在客户端浏览器里把该站点加入“允许麦克风”的例外（不同版本入口不同，以实际浏览器为准）。
2. 改用 HTTPS：`https://192.168.1.174:8788`。首次访问需要信任本机生成的本地 CA：

```text
http://192.168.1.174:8787/api/lan/ca-cert
```

下载证书后安装到“受信任的根证书颁发机构”，再重启浏览器。证书只用于局域网内的这台电脑，不要分发到不可信环境。

## 安全边界

- 系统当前没有登录认证，只适合可信局域网。
- 不要配置路由器端口映射，不要把 `8787` / `8788` 暴露到公网。
- 不在公共 Wi-Fi 下开启局域网访问。
- 换电脑后重新执行 `scripts\create-lan-cert.ps1`，旧证书里的 IP 不再适用。

## 排查

- 另一台电脑打不开：先在本机访问 `http://127.0.0.1:8787/api/health`，确认服务正常。
- 本机正常、别的电脑不通：检查防火墙规则、两台电脑是否在同一网段、Windows 网络类型是否为“公用网络”。
- 换端口启动：`npm run start:lan -- -Port 8797 -HttpsPort 8798`，访问地址同步改成新端口。
- 端口被占用：脚本会提示。先关闭占用程序，或换一组端口。
